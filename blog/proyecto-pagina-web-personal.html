Proyecto: Página Web Personal

Introducción

La idea de desarrollar una página web personal se originó mucho antes de comenzar este proyecto. Desde hace tiempo tenía pensado contar con un espacio propio en Internet en el cual pudiera presentarme ante el mundo, compartir mis habilidades y mostrar los trabajos que fuera realizando a lo largo de mi formación académica y profesional.

Considero que tener un sitio web independiente es una herramienta útil para establecer contactos, ya que basta con compartir una dirección URL para que otras personas puedan conocerme y ponerse en contacto conmigo. También puede funcionar como portafolio para futuros empleadores, permitiéndoles conocer mis proyectos.

Sin embargo, aunque tenía esa idea, no había encontrado la motivación suficiente para llevarla a cabo. Esto cambió cuando, en la materia de "Competencia Digital", se nos dio la oportunidad de realizar un proyecto de nuestra elección. Aproveché esa oportunidad para convertir una idea en realidad.

De esa forma se originó este sitio web, desarrollado únicamente con HTML y CSS. Este proyecto me permitió adquirir nuevos conocimientos, ponerlos en práctica y familiarizarme con distintas herramientas utilizadas en el ámbito del desarrollo web.

En este artículo documentaré el proceso que llevé a cabo, desde la preparación del entorno de trabajo y el aprendizaje de los fundamentos necesarios hasta el desarrollo y la publicación del sitio. Mi intención es que esta experiencia pueda servir como referencia para otros estudiantes interesados en crear su propia página web.

Preparación del entorno de desarrollo

Instalación de Fedora Linux

Antes de comenzar con el desarrollo del proyecto, fue necesario preparar un entorno de trabajo adecuado. Para ello, decidí utilizar Linux como sistema operativo, aunque opté por explorar distintas distribuciones antes de elegir una.

Primero probé Ubuntu, pero tuve diversos problemas que interrumpían constantemente mi ritmo de trabajo. No pude determinar si esos inconvenientes se debían al sistema operativo en sí o a las características de mi computadora, puesto que uso una Lenovo ThinkPad T440p, la cual tiene ya varios años de antigüedad.

Después utilicé Linux Mint, una distribución que me dejó una muy buena impresión por su funcionamiento y apariencia, bastante familiar para mí debido a su parecido con Windows. Sin embargo, noté que incluía algunas herramientas y opciones adicionales que realmente no necesitaba para el proyecto y que terminaban convirtiéndose más en una distracción que en un apoyo.

Finalmente, usé Fedora, que funcionó correctamente desde el primer día. Su apariencia y funcionamiento general me permitieron concentrarme en el aprendizaje y desarrollo del proyecto sin las interrupciones que había experimentado anteriormente con las otras distribuciones. Por estas razones, elegí Fedora como mi sistema operativo de trabajo.

Para instalarlo, descargué la imagen ISO del sistema desde el sitio web oficial y seguí las instrucciones proporcionadas para verificar su autenticidad e integridad. Después, desde Windows, utilicé un programa llamado Rufus para preparar una memoria USB de instalación.

Por último, instalé el sistema operativo en una unidad M.2 independiente del SSD donde tenía instalado Windows, de tal forma que pudiera disponer de ambos sistemas por separado.

Una vez instalado Fedora y comprobado su correcto funcionamiento, contaba con una base estable para comenzar a instalar y configurar las herramientas necesarias para el desarrollo de mi proyecto web.

Instalación de Visual Studio Code

Para escribir y editar el código del proyecto, decidí utilizar Visual Studio Code, un editor de código recomendado tanto por The Odin Project como por numerosos desarrolladores.

Después de comenzar a utilizarlo, comprobé que era una herramienta adecuada para mis necesidades, ya que me permitía trabajar de manera cómoda y concentrarme en el desarrollo del proyecto sin complicaciones innecesarias.

Para instalarlo en Fedora Linux, seguí las instrucciones proporcionadas en la documentación oficial de Visual Studio Code para Linux .

Una vez instalado, lo utilicé para abrir los archivos del proyecto directamente desde la terminal mediante el comando code, así como para escribir y editar el código HTML y CSS de mi página web.

Instalación de Chromium

Para comprobar el funcionamiento de mi página web, necesitaba un navegador basado en Chromium, ya que Google Chrome es uno de los navegadores más utilizados. De esta manera, podía asegurarme de que el sitio se visualizara y funcionara correctamente en un entorno similar al utilizado por muchos usuarios.

Elegí Chromium porque prefería utilizar una alternativa de código abierto, sin algunas de las integraciones y servicios propios de Google Chrome.

Su instalación fue sencilla, ya que únicamente tuve que buscarlo en la tienda de aplicaciones de Fedora e instalarlo desde allí. Posteriormente, lo utilicé para visualizar mi página web y comprobar los cambios que realizaba durante su desarrollo.

La terminal de Linux y Git

Antes de comenzar a trabajar en el proyecto, dediqué parte de mi tiempo a familiarizarme con la terminal de Linux. Para ello, utilicé como referencia el material educativo The Unix Shell de Software Carpentry.

Mi objetivo no era aprender todas las posibilidades que ofrece la terminal, sino adquirir los conocimientos fundamentales para desenvolverme en el entorno de desarrollo. Por esta razón, me concentré en comprender su funcionamiento y aprender los comandos necesarios para trabajar con archivos y directorios.

También comencé a estudiar Git, utilizando como referencia el libro Pro Git y el artículo How to Write a Git Commit Message . Estos recursos me ayudaron a familiarizarme con el control de versiones y las convenciones para escribir mensajes de commit.

No dediqué demasiado tiempo a esta etapa de estudio, ya que mi intención era comenzar a trabajar cuanto antes y continuar aprendiendo mediante la práctica. A lo largo del proyecto, fui reforzando estos conocimientos conforme necesitaba utilizar nuevas herramientas y comandos.

Aprendizaje de los fundamentos

The Odin Project

Al comenzar mi aprendizaje sobre desarrollo web, no tenía claro qué curso utilizar. Consideré distintas alternativas, entre ellas freeCodeCamp y The Odin Project, mientras buscaba el recurso que pudiera ofrecerme la mejor formación posible.

Sin embargo, después de investigar distintas opciones, comprendí que no existe un curso perfecto y que lo verdaderamente importante era aprender los fundamentos del desarrollo web y ponerlos en práctica. Con esto en mente, finalmente me decidí por The Odin Project.

Una de las características que más me gustaron de este curso fue su metodología de enseñanza. Además de proporcionar las lecciones, ofrece enlaces a documentación y recursos externos que permiten profundizar en los temas estudiados. También incluye ejercicios prácticos para aplicar los conocimientos adquiridos.

Esta combinación de teoría, investigación y práctica me resultó especialmente útil, ya que me permitió desarrollar una mejor comprensión de los conceptos y comenzar a utilizarlos por mi cuenta. Por estas razones, considero que elegir The Odin Project fue una buena decisión para iniciar mi formación en desarrollo web.

HTML

Para comenzar a aprender HTML, estudié las lecciones correspondientes al bloque HTML Foundations de The Odin Project, así como los recursos adicionales proporcionados al final de cada lección.

Durante esta etapa, aprendí que HTML es un lenguaje de marcado utilizado para definir la estructura y el contenido de las páginas web. Estudié el funcionamiento de las etiquetas, los elementos y sus atributos, así como la estructura básica que debe tener un documento HTML.

También aprendí a organizar contenido mediante encabezados, párrafos y listas, además de utilizar enlaces para conectar diferentes páginas y recursos. Por último, estudié cómo incorporar imágenes y trabajar con rutas relativas y absolutas.

Estos conocimientos fueron fundamentales para desarrollar mi página personal, ya que me permitieron organizar su contenido en distintas secciones, incorporar una fotografía, agregar enlaces de contacto y estructurar la información de los proyectos que quería presentar.

CSS

Después de estudiar HTML, continué con las lecciones del bloque CSS Foundations de The Odin Project, así como los recursos adicionales proporcionados al final de cada lección.

Durante esta etapa, aprendí que CSS es un lenguaje de hojas de estilo utilizado para controlar la presentación visual de las páginas web. Estudié cómo vincular un archivo CSS con un documento HTML, utilizar selectores y aplicar propiedades para modificar aspectos como los colores, las fuentes, los tamaños y los bordes de los elementos.

También estudié el funcionamiento de la cascada, la especificidad y la herencia, conceptos que permiten comprender cómo se aplican las distintas reglas de estilo. Además, aprendí sobre el modelo de caja, las propiedades margin y padding, las diferencias entre elementos de bloque y en línea, y el uso de las herramientas de inspección del navegador para examinar y probar estilos.

Estos conocimientos me permitieron definir la apariencia de mi página personal, establecer una paleta de colores, seleccionar tipografías y ajustar los espacios entre los distintos elementos. También fueron fundamentales para diseñar las tarjetas de los proyectos y las secciones de contacto y apoyo, manteniendo una presentación visual consistente.

Flexbox

Después de estudiar los fundamentos de CSS, continué con las lecciones del bloque Flexbox de The Odin Project, así como los recursos adicionales proporcionados al final de cada lección.

Durante esta etapa, aprendí que Flexbox es un sistema de diseño de CSS que permite organizar y distribuir elementos dentro de un contenedor. Estudié el funcionamiento de los contenedores flexibles y sus elementos, así como las propiedades que permiten controlar su tamaño y distribución.

También aprendí sobre los ejes principal y transversal, y cómo estos cambian dependiendo de la dirección de los elementos. Además, estudié propiedades como flex-direction, justify-content y align-items, que permiten controlar la orientación y alineación de los elementos dentro de un contenedor.

Estos conocimientos me resultaron especialmente útiles para organizar los elementos de la sección de contacto de mi página personal. Mediante Flexbox, pude distribuir los enlaces verticalmente, centrarlos y establecer un espacio uniforme entre ellos, manteniendo una presentación consistente en distintos tamaños de pantalla.

Flujo de trabajo del proyecto

Para demostrar el proceso de desarrollo de una página web, creé un proyecto de ejemplo llamado «Búho Hacker», utilizando HTML y CSS.

A continuación, explicaré las principales etapas del proceso, desde la creación del repositorio hasta la organización visual de la página. También incluiré capturas de pantalla para ilustrar los pasos más importantes.

Creación del repositorio en GitHub y clonación en terminal

Para comenzar, creé un repositorio público en GitHub llamado «ejemplo-pagina-web». Desde la página principal de GitHub, seleccioné el símbolo «+» y después la opción «New repository».

En el formulario de creación, escribí el nombre del repositorio, dejé la descripción en blanco, seleccioné la visibilidad pública y activé la opción para incluir un archivo README. Las demás opciones las conservé con sus valores predeterminados.

Después de crear el repositorio, GitHub mostró su página principal, donde podía consultar los archivos y realizar futuras modificaciones.

Para descargar una copia del repositorio en mi computadora, presioné el botón verde «Code», seleccioné la opción «SSH» y copié la dirección proporcionada por GitHub.

Para utilizar SSH, primero es necesario configurar la conexión entre nuestra computadora y GitHub. Yo realicé este procedimiento siguiendo las instrucciones de The Odin Project .

Finalmente, abrí la terminal y creé una carpeta llamada «ejemplo» utilizando el comando «mkdir». Después ingresé a ella con «cd» y ejecuté «git clone» seguido de la dirección SSH que había copiado.

Una vez completada la clonación, utilicé «ls -F» para comprobar que el repositorio se había descargado. Ingresé a la carpeta «ejemplo-pagina-web» con «cd» y ejecuté nuevamente «ls -F» para verificar que contenía el archivo README.md.

Agregar descripción sobre el proyecto al archivo README.md

Después de clonar el repositorio, utilicé el comando «code .» desde la terminal para abrir la carpeta del proyecto en Visual Studio Code.

Al abrir el proyecto, Visual Studio Code mostró un aviso de seguridad llamado «Restricted Mode». Como se trataba de un repositorio creado por mí, seleccioné la opción «In a Trusted Folder» para confiar en su contenido.

A continuación, edité el archivo README.md para agregar una breve descripción del proyecto y explicar su propósito. Después guardé los cambios utilizando «Ctrl + S».

Regresé a la terminal y utilicé «git status» para revisar los cambios realizados. Después ejecuté «git add .» para prepararlos y consulté nuevamente su estado. Finalmente, utilicé «git commit .» para registrar las modificaciones.

Para escribir los mensajes de los commits desde Visual Studio Code, había configurado previamente este programa como editor de Git. Seguí las instrucciones de The Odin Project para realizar esta configuración.

Al ejecutar el comando para crear el commit, Visual Studio Code abrió una pestaña donde escribí el mensaje correspondiente. Después guardé el archivo y cerré la pestaña para completar la operación.

Al regresar a la terminal, comprobé que Git había registrado el commit correctamente.

Después utilicé «git status» para revisar el repositorio y ejecuté «git push origin main» para enviar los cambios a GitHub. Finalmente, consulté nuevamente su estado.

Al visitar nuevamente el repositorio en GitHub, pude comprobar que el archivo README.md mostraba la descripción que había agregado.

GitHub también permite consultar el historial de commits. Para comprobarlo, abrí la lista de commits del repositorio y seleccioné el más reciente.

Al abrir el commit, GitHub mostró la información del cambio realizado y las modificaciones registradas en el archivo. Esto permite consultar cómo ha evolucionado un proyecto a lo largo del tiempo.

Desarrollo de la estructura de la página con HTML

Una vez preparado el repositorio, comencé a crear los archivos necesarios para desarrollar la página web. Primero utilicé «ls -F» para consultar su contenido y después ejecuté «touch index.html style.css» para crear los archivos HTML y CSS. También creé una carpeta llamada «images» utilizando «mkdir». Finalmente, abrí el proyecto en Visual Studio Code con «code .».

Después escribí la estructura HTML de la página, incluyendo una imagen de perfil animada, una breve presentación y una sección con diferentes opciones de contacto. En esta primera etapa no vinculé el archivo CSS, ya que quería mostrar cómo se presenta una página web utilizando únicamente HTML.

Para simplificar esta demostración, escribí toda la estructura HTML antes de registrar los cambios. Sin embargo, durante el desarrollo de un proyecto es recomendable realizar commits pequeños y enfocados, conocidos como «atomic commits». Estos permiten mantener un historial más claro de las modificaciones realizadas. Puedes consultar una explicación sobre cuándo realizar un commit en The Odin Project .

Una vez terminada la estructura inicial, utilicé «git status» para revisar los cambios y «git add index.html images/» para prepararlos. Después consulté nuevamente el estado del repositorio y ejecuté «git commit .» para registrar el trabajo.

Escribí el mensaje del commit en Visual Studio Code y guardé el archivo para completar la operación. Después regresé a la terminal y utilicé «git push origin main» para enviar los cambios a GitHub.

Al consultar nuevamente el historial de commits en GitHub, pude comprobar que el cambio había quedado registrado.

Para visualizar el resultado, abrí otra terminal, ingresé a la carpeta del repositorio y utilicé «ls -F» para consultar sus archivos. Después ejecuté «chromium-browser index.html» para abrir la página directamente en Chromium.

El navegador mostró la página con los estilos predeterminados de HTML. Aunque todavía no tenía un diseño personalizado, ya era posible visualizar la imagen, leer la presentación y utilizar los enlaces de contacto.

Posteriormente, realicé un cambio pequeño en el archivo HTML: agregué los atributos «width» y «height» a la imagen para especificar sus dimensiones originales. Este cambio fue registrado por separado, como ejemplo de un commit enfocado en una modificación concreta.

Para registrar la modificación, utilicé «git status», «git add index.html» y nuevamente «git status». Después ejecuté «git commit .», escribí el mensaje correspondiente en Visual Studio Code y envié los cambios a GitHub mediante «git push origin main».

Finalmente, consulté nuevamente el historial de commits en GitHub para comprobar que la modificación se había registrado correctamente.

Aplicación de estilos con CSS

Una vez terminada la estructura HTML, comencé a personalizar la apariencia de la página utilizando CSS. Como el proyecto ya estaba abierto en Visual Studio Code, primero agregué una etiqueta «link» dentro del elemento «head» para vincular el archivo style.css con index.html.

Después escribí las reglas CSS para modificar los colores de fondo y texto, establecer la tipografía y ajustar los espacios entre los elementos. También definí el tamaño de la imagen de perfil y agregué un borde a su alrededor.

Además, personalicé los enlaces para que cambiaran de color al colocar el cursor sobre ellos o seleccionarlos mediante la tecla «Tab». Para facilitar la navegación con el teclado, también agregué un contorno visible a los enlaces seleccionados.

Para comprobar el resultado, regresé a Chromium y actualicé la pestaña donde tenía abierta la página. Los cambios permitieron visualizar una apariencia personalizada sin modificar el contenido HTML.

Una vez comprobados los estilos, regresé a la terminal y utilicé «git status» para revisar las modificaciones. Después ejecuté «git add .» para prepararlas, consulté nuevamente el estado del repositorio y utilicé «git commit .» para registrar los cambios.

Escribí el mensaje del commit en Visual Studio Code, guardé el archivo y cerré la pestaña para completar la operación.

Finalmente, ejecuté «git push origin main» desde la terminal para enviar los cambios a GitHub.

Al consultar el historial de commits en GitHub, comprobé que las modificaciones habían quedado registradas correctamente.

Posicionamiento de los elementos de la página con Flexbox

Después de aplicar los estilos visuales, continué organizando los elementos de la página. Primero ajusté los márgenes de los párrafos para reducir el espacio entre ellos y conseguir una presentación más compacta.

Después utilicé Flexbox para organizar la lista de contacto. Establecí una distribución vertical con «flex-direction: column», centré sus elementos con «align-items: center» y ajusté su separación utilizando «gap». También eliminé las viñetas y los espacios predeterminados de la lista.

A continuación, utilicé Flexbox para distribuir el contenido general de la página. Apliqué reglas a los elementos «main», «header» y «section» para centrar el contenido, organizarlo verticalmente y controlar los espacios disponibles. También limité el ancho de las secciones y centré sus textos.

Para comprobar los cambios, regresé a Chromium y actualicé la página. El contenido ahora aparecía centrado y organizado verticalmente, con una separación más uniforme entre los diferentes elementos.

Una vez terminado el posicionamiento, utilicé «git status» para revisar los cambios, «git add .» para prepararlos y nuevamente «git status» para comprobar su estado. Después ejecuté «git commit .» para registrarlos.

Escribí el mensaje del commit en Visual Studio Code, guardé el archivo y cerré la pestaña. Finalmente, ejecuté «git push origin main» desde la terminal para enviar los cambios a GitHub.

Después consulté el historial de commits en GitHub para comprobar que las modificaciones habían quedado registradas correctamente.

Como último ajuste visual, agregué una regla CSS para los elementos «li» de la lista de contacto. Definí su ancho, agregué espacio interior mediante «padding» e incorporé un color de fondo, un borde y esquinas redondeadas. Así, cada opción de contacto adquirió una apariencia de tarjeta.

Después actualicé la página en Chromium para comprobar el resultado. Las opciones de contacto ahora se mostraban como tarjetas individuales, manteniendo su alineación y separación gracias a Flexbox.

Para registrar este último cambio, ejecuté «git status», «git add .», nuevamente «git status» y «git commit .». Después escribí el mensaje correspondiente en Visual Studio Code y envié el commit a GitHub con «git push origin main».

Finalmente, revisé nuevamente el historial de commits en GitHub para confirmar que los últimos cambios se habían registrado correctamente.

De local a global: publicación del sitio web

Después de terminar el desarrollo de la página web, el siguiente paso fue publicarla en Internet para que cualquier persona pudiera visitarla.

Para ello, utilicé GitHub Pages, un servicio que permite publicar sitios web directamente desde un repositorio de GitHub. Posteriormente, configuré un dominio personalizado para que la página tuviera una dirección propia.

Publicación del sitio mediante GitHub Pages

Una vez terminado el desarrollo de la página, el siguiente paso fue publicarla utilizando GitHub Pages. Para comenzar, ingresé a la página principal del repositorio en GitHub.

Después seleccioné la pestaña «Settings» para acceder a las opciones de configuración del repositorio.

Dentro de los ajustes, ingresé al apartado «Pages». En la configuración de publicación, seleccioné la rama «main» como fuente del sitio web.

Después presioné el botón «Save» para guardar la configuración. GitHub mostró un mensaje de confirmación indicando que la fuente de publicación había sido guardada.

Tras actualizar la página de configuración, pude comprobar que GitHub Pages había publicado el sitio correctamente y mostraba un enlace para visitarlo.

Finalmente, seleccioné la opción «Visit site» para abrir la página en una nueva pestaña del navegador. De esta manera, el proyecto dejó de estar disponible únicamente en mi computadora y pasó a ser accesible desde Internet.
