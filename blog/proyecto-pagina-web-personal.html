Proyecto: Página Web Personal

Introducción

La idea de desarrollar una página web personal se originó mucho antes de comenzar este proyecto. Desde hace tiempo tenía pensado contar con un espacio propio en internet en el cual pudiera presentarme ante el mundo, compartir mis habilidades y mostrar los trabajos que fuera realizando a lo largo de mi formación académica y profesional.

Considero que tener un sitio web independiente es una herramienta muy útil para establecer contactos, ya que basta con compartir una dirección URL para que otras personas puedan conocerte y ponerse en contacto contigo. También puede funcionar como un portafolio para mostrar a futuros empleadores tus capacidades como desarrollador.

Sin embargo, aunque tenía esa idea, no había encontrado la motivación suficiente para llevarla a cabo. Esto cambió cuando, en la materia de "Competencia Digital", se nos dio la oportunidad de realizar un proyecto de nuestra elección. Aproveché esa oportunidad para convertir una idea en realidad.

De esa forma surgió este sitio web, desarrollado únicamente con HTML y CSS. Este proyecto me permitió adquirir nuevos conocimientos, ponerlos en práctica y familiarizarme con distintas herramientas utilizadas en el ámbito del desarrollo web.

En este artículo compartiré el proceso que llevé a cabo, desde la preparación del entorno de trabajo y el aprendizaje de los fundamentos necesarios hasta el desarrollo y la publicación del sitio. Mi intención es que esta experiencia pueda servir como referencia para otros estudiantes interesados en crear su propia página web.

Preparación del entorno de desarrollo

Instalación de Fedora Linux

Antes de comenzar con el desarrollo del proyecto, fue necesario preparar un entorno de trabajo adecuado. Para ello, decidí utilizar Linux como sistema operativo, aunque opté por explorar distintas distribuciones antes de elegir una en específico.

Primero intenté usar Ubuntu, pero tuve diversos problemas que interrumpían constantemente mi ritmo de trabajo. No pude determinar si esos inconvenientes se debían al sistema operativo en sí o a las características de mi computadora, puesto que uso una Lenovo ThinkPad T440p, la cual tiene ya varios años de antigüedad.

Después utilicé Linux Mint, una distribución que me dejó una muy buena impresión por su funcionamiento y apariencia, bastante familiar para mí debido a su parecido con Windows. Sin embargo, noté que incluía algunas herramientas, programas y opciones adicionales que realmente no necesitaba para el proyecto y que terminaban convirtiéndose más en una distracción que en un apoyo.

Finalmente, usé Fedora Linux, que funcionó correctamente desde el primer instante. Su apariencia y funcionamiento general me permitieron concentrarme en el aprendizaje y desarrollo del proyecto sin las interrupciones que había experimentado anteriormente con las otras distribuciones. Por estas razones, elegí a Fedora como mi sistema operativo de trabajo.

Para instalarlo, descargué la imagen ISO del sistema desde el sitio web oficial y seguí las instrucciones proporcionadas para verificar la autenticidad e integridad del archivo. Después, desde Windows, utilicé un programa llamado Rufus para preparar una memoria USB de instalación.

Por último, instalé el sistema operativo en una unidad M.2 de mi computadora, independiente del SSD en el que tenía instalado Windows, de tal forma que pudiera disponer de ambos sistemas por separado. Esto no es realmente necesario, pero lo hice de esa forma porque no quería que, en caso de que hubiera un problema al momento de instalar/usar Linux, eso afectara de alguna manera a mi partición de Windows.

Una vez instalado el sistema operativo y habiendo comprobado su correcto funcionamiento, contaba con una base estable para comenzar a instalar y configurar las herramientas necesarias para el desarrollo del proyecto.

Instalación de Visual Studio Code

Para escribir y editar el código del proyecto, decidí utilizar Visual Studio Code, un editor de código bastante reconocido y recomendado por muchos desarrolladores.

Después de comenzar a utilizarlo, comprobé que era una herramienta adecuada para mis necesidades, ya que me permitía trabajar de manera cómoda y concentrarme en el desarrollo del proyecto sin complicaciones innecesarias.

Para instalarlo en Fedora, simplemente seguí las instrucciones adecuadas, proporcionadas en la documentación oficial de Visual Studio Code para Linux.

Una vez instalado, lo utilicé para abrir los archivos del proyecto directamente desde la terminal mediante el comando "code", así como para escribir y editar el código HTML y CSS de la página web.

Instalación de Chromium

Para las pruebas de apariencia y funcionamiento del sitio, necesitaba hacer uso de un navegador que fuese utilizado por la mayoría de los usuarios.

Elegí Chromium por ser una alternativa de código abierto, sin algunas de las características propias de Google Chrome.

Su instalación fue sencilla, ya que únicamente tuve que buscarlo en la tienda de aplicaciones de Fedora y descargarlo desde ahí. Posteriormente, lo utilicé para visualizar la página web y comprobar los cambios realizados durante su desarrollo.

La terminal de Linux y Git

Con el fin de agilizar el flujo de trabajo, dediqué parte de mi tiempo a familiarizarme con la terminal de Linux. Para ello, utilicé como referencia el material educativo The Unix Shell de Software Carpentry.

Mi objetivo no era aprender absolutamente todo lo que la terminal ofrece, simplemente quería adquirir los conocimientos básicos para desarrollar el proyecto haciendo uso de la misma. Por esta razón, me enfoqué en comprender su funcionamiento y aprender los comandos necesarios para trabajar con archivos y directorios.

También comencé a estudiar Git, utilizando como referencia el libro Pro Git y el artículo How to Write a Git Commit Message. Estos recursos me ayudaron a entender de qué trata el control de versiones y las convenciones usadas para escribir buenos mensajes de "commit".

A lo largo del proyecto, fui reforzando estos conocimientos y aprendiendo mediante la práctica.

Aprendizaje de los fundamentos

The Odin Project

Al comenzar mi aprendizaje sobre desarrollo web, no tenía muy claro qué curso utilizar. Consideré distintas alternativas, entre ellas freeCodeCamp y The Odin Project, mientras encontraba el recurso que pudiera ofrecerme la mejor formación posible.

Sin embargo, después de investigar, comprendí que no existe en realidad un "curso perfecto" y que lo verdaderamente importante era aprender los fundamentos del desarrollo web y ponerlos en práctica. Con esto en mente, finalmente me decidí por The Odin Project.

Una de las características que más me gustaron de este curso fue su metodología de enseñanza. Además de proporcionar las lecciones, ofrece enlaces a documentación y recursos externos que permiten profundizar en los temas estudiados. También incluye ejercicios prácticos para aplicar los conocimientos adquiridos.

Esta combinación de teoría, investigación y práctica me pareció muy útil e interesante, ya que me permitió desarrollar una mejor comprensión de los conceptos y así, comenzar a utilizarlos por mi cuenta. Por estas razones, considero que elegir a The Odin Project fue una muy buena decisión para iniciar mi viaje en el mundo del desarrollo web.

HTML

Para comenzar a aprender HTML, estudié las lecciones correspondientes al bloque HTML Foundations del curso, así como los recursos adicionales proporcionados al final de cada lección.

Durante esta etapa, aprendí que HTML es un lenguaje utilizado para definir la estructura y el contenido de las páginas web. Estudié el funcionamiento de las etiquetas, los elementos y sus atributos, así como la estructura básica que debe tener un documento HTML.

También aprendí a organizar contenido mediante encabezados, párrafos y listas, además de utilizar enlaces para conectar diferentes páginas y recursos. Por último, estudié cómo incorporar imágenes y trabajar con rutas relativas y absolutas.

Estos conocimientos fueron fundamentales para desarrollar mi página personal, ya que me permitieron organizar su contenido en distintas secciones, incorporar una fotografía, agregar enlaces de contacto y estructurar la información de los proyectos a presentar.

CSS

Después de estudiar HTML, continué con las lecciones del bloque CSS Foundations.

En esta parte, aprendí que CSS es un lenguaje utilizado para controlar la presentación visual de las páginas web. Ví cómo vincular un archivo CSS con un documento HTML, utilizar selectores y aplicar propiedades para modificar aspectos como los colores, la tipografía, los tamaños y los bordes de los elementos.

También estudié el funcionamiento de la cascada, la especificidad y la herencia, conceptos que permiten comprender cómo se aplican las distintas reglas de estilo. Además, aprendí sobre el modelo de caja, las propiedades "margin" y "padding", las diferencias entre elementos de bloque y en línea, y el uso de las herramientas de inspección del navegador para examinar y probar estilos.

Todo esto me permitió definir la apariencia de mi página personal, establecer una paleta de colores, seleccionar tipografías y ajustar los espacios entre los distintos elementos. También pude diseñar las "tarjetas" de los proyectos y las secciones de contacto y apoyo, manteniendo así, una presentación visual consistente.

Flexbox

Por último, lleve a cabo las lecciones del bloque Flexbox.

Aquí aprendí que Flexbox es un sistema de diseño parte de CSS que permite organizar y distribuir elementos dentro de un contenedor. Estudié el funcionamiento de los contenedores flexibles y sus elementos, así como las propiedades que permiten controlar su tamaño y distribución.

También aprendí sobre los ejes principal y transversal, y cómo estos cambian dependiendo de la dirección de los elementos. Además, estudié propiedades como "flex-direction", "justify-content" y "align-items", que permiten controlar la orientación y alineación de los elementos dentro de un contenedor.

Esto fue algo realmente útil para organizar los elementos de la sección de contacto del sitio. Mediante Flexbox, pude distribuir los enlaces verticalmente, centrarlos y establecer un espacio uniforme entre ellos, logrando con eso una presentación consistente en diferentes tamaños de pantalla.

Flujo de trabajo del proyecto

La siguiente es una pequeña demostración del proceso de desarrollo mediante la creación de una página web "mini".

Explicaré las principales etapas del proceso, desde la creación del repositorio hasta la organización visual del sitio. Asimismo, incluiré capturas de pantalla para ilustrar los pasos que se lleven a cabo.

Creación del repositorio en GitHub y clonación en terminal

Para comenzar, creé un repositorio público llamado "ejemplo-pagina-web". Desde la página principal de GitHub, seleccioné el símbolo de "+" y después la opción "New repository".

En el formulario de creación, escribí el nombre del repositorio, dejé la descripción en blanco, seleccioné la visibilidad pública y activé la opción para incluir un archivo README. Las demás opciones las dejé con sus valores predeterminados.

Después de crear el repositorio, GitHub mostró su página principal.

Para descargar una copia del repositorio en mi computadora, presioné el botón verde "Code", seleccioné la opción "SSH" y copié la dirección proporcionada.

Para utilizar la opción anteriormente mencionada, primero es necesario configurar la conexión entre nuestra computadora y GitHub. Yo realicé este procedimiento siguiendo las instrucciones del artículo Setting up Git.

Finalmente, abrí la terminal y creé una carpeta llamada "ejemplo" utilizando el comando "mkdir". Después, ingresé a ella usando "cd" y ejecuté "git clone" seguido de la dirección SSH que había copiado.

Una vez terminada la clonación, utilicé "ls -F" para comprobar que el repositorio se había descargado. Ingresé a la carpeta "ejemplo-pagina-web" con "cd" y ejecuté nuevamente "ls -F" para verificar que contenía el archivo README.md.

Agregar descripción sobre el proyecto al archivo README.md

Ya con una copia local en mi computadora, utilicé el comando "code ." desde la terminal para abrir la carpeta del proyecto en Visual Studio Code.

Al abrir el proyecto, Visual Studio Code mostró un aviso de seguridad. Como se trataba de un trabajo hecho por mí, hice click en el botón de "Trust" para confiar en su contenido.

A continuación, edité el archivo README.md para agregar una breve descripción del proyecto y explicar su propósito. Después guardé los cambios utilizando "Ctrl + S".

Regresé a la terminal y utilicé "git status" para revisar los cambios realizados. Después ejecuté "git add ." para prepararlos y consulté nuevamente su estado. Finalmente, utilicé "git commit ." para registrar las modificaciones.

Para escribir los mensajes de los "commits" desde Visual Studio Code, seleccioné este programa como editor de Git. Para ello, seguí las instrucciones mostradas en: Changing the Git commit message editor.

Al ejecutar el comando para crear el "commit", Visual Studio Code abrió una pestaña en la que escribí el mensaje correspondiente. Después guardé el archivo y cerré la pestaña para completar la operación.

Al regresar a la terminal, comprobé que Git había registrado el "commit" correctamente.

Después utilicé "git status" para revisar el estado actual del repositorio y ejecuté "git push origin main" para enviar los cambios a GitHub. Y consulté el estado otra vez.

Al visitar el repositorio en GitHub, pude comprobar que el archivo README.md mostraba la descripción que había agregado.

GitHub también permite consultar el historial de "commits". Para comprobarlo, abrí la lista que aparece en el repositorio y seleccioné el más reciente.

Al abrir el "commit", GitHub mostró la información del cambio realizado y las modificaciones registradas en el archivo. Esto permite consultar la manera en la que ha ido evolucionado un proyecto a lo largo del tiempo.

Desarrollo de la estructura de la página con HTML

Una vez preparado el repositorio, comencé a crear los archivos necesarios para desarrollar la página web. Esto usando el comando "touch" y nombrando los documentos como "index.html" y "style.css". También creé una carpeta llamada "images". Finalmente, abrí el proyecto en Visual Studio Code.

Después escribí la estructura HTML de la página, incluyendo un GIF, una breve presentación y una sección con diferentes opciones de contacto. En esta primera etapa no vinculé el archivo CSS, ya que quería mostrar cómo se presenta una página web utilizando únicamente HTML.

Para simplificar esta demostración, escribí toda la estructura HTML antes de registrar los cambios. Sin embargo, durante el desarrollo de un proyecto es recomendable realizar "commits" pequeños y precisos, conocidos también como "atomic commits". Estos permiten mantener un historial más claro de las modificaciones realizadas. Puedes consultar una explicación sobre cuándo realizar un commit en When to commit.

Una vez terminada la estructura inicial, utilicé "git status" para revisar los cambios y "git add index.html images/" para prepararlos. Después consulté nuevamente el estado del repositorio y ejecuté "git commit ." para registrar el trabajo.

Escribí el mensaje del "commit" en Visual Studio Code y guardé el archivo para completar la operación. Después regresé a la terminal y utilicé "git push origin main" para enviar los cambios a GitHub.

Al consultar nuevamente el historial de "commits" en GitHub, pude comprobar que el cambio había quedado registrado.

Para visualizar el resultado, abrí otra terminal, ingresé a la carpeta del repositorio y consulté sus archivos. Después ejecuté "chromium-browser index.html" para abrir la página directamente en Chromium.

El navegador mostró la página con los estilos predeterminados de HTML. Aunque todavía no tenía un diseño personalizado, ya era posible visualizar el GIF, leer la presentación y utilizar los enlaces de contacto.

Posteriormente, realicé un cambio pequeño en el archivo HTML: agregué los atributos "width" y "height" al GIF para especificar sus dimensiones originales. Este cambio fue registrado por separado, como ejemplo de un "atomic commit" de una modificación concreta.

Para registrar la modificación, utilicé "git status", "git add index.html" y nuevamente "git status". Después ejecuté "git commit .", escribí el mensaje correspondiente en Visual Studio Code y envié los cambios a GitHub mediante "git push origin main".

Al consultar nuevamente el historial de "commits" en GitHub, la modificación se había registrado correctamente.

Aplicación de estilos con CSS

Una vez terminada la estructura HTML, comencé a personalizar la apariencia de la página utilizando CSS. Como el proyecto ya estaba abierto en Visual Studio Code, primero agregué una etiqueta "link" dentro de la sección "head" en index.html para enlazar el archivo con style.css.

Después escribí las reglas CSS necesarias para modificar los colores de fondo y texto, establecer la tipografía y ajustar los espacios entre los elementos. También definí el tamaño del GIF y agregué un marco a su alrededor.

Además, personalicé los enlaces para que cambiaran de color al colocar el cursor sobre ellos o seleccionarlos mediante la tecla "Tab". Para facilitar la navegación con el teclado, también agregué un contorno visible a los enlaces seleccionados.

Para comprobar el resultado, regresé a Chromium y actualicé la pestaña en donde tenía abierta la página. Los cambios permitieron observar como la apariencia cambió sin modificar el contenido HTML.

Regresé a la terminal para revisar las modificaciones, las preparé, consulté nuevamente el estado del repositorio y registré los cambios.

Escribí el mensaje del "commit", guardé el archivo y cerré la pestaña para completar la operación.

Finalmente, envié los cambios a GitHub.

Consulté el historial y comprobé que las modificaciones habían quedado registradas.

Posicionamiento de los elementos de la página con Flexbox

Después de aplicar los estilos visuales, continué organizando los elementos de la página. Primero ajusté los márgenes de los párrafos para reducir el espacio entre ellos y, de esa forma, conseguir una presentación más compacta.

Después utilicé Flexbox para organizar la lista de contacto. Establecí una distribución vertical con "flex-direction: column", centré sus elementos con "align-items: center" y ajusté el espacio de separación utilizando "gap". También eliminé los puntos y los espacios predeterminados de la lista.

A continuación, me dediqué a distribuir el contenido general de la página. Apliqué reglas a los elementos "main", "header" y "section" para centrar el contenido, organizarlo verticalmente y controlar los espacios disponibles. También limité el ancho de las secciones y centré sus textos.

Para comprobar los cambios, regresé a Chromium y actualicé la página. El contenido ahora aparecía centrado y organizado verticalmente, con una separación más uniforme entre los diferentes elementos.

Una vez terminado el posicionamiento, revisé los cambios en la terminal, los preparé y después ejecuté el comando necesario para registrarlos.

Escribí el mensaje del "commit", guardé el archivo y cerré la pestaña. Ejecuté el comando requerido desde la terminal para enviar los cambios a GitHub.

Después consulté el historial de "commits" para corroborar que todo estuviera en orden.

Como último ajuste visual, agregué una regla en CSS para los elementos "li" de la lista de contacto. Definí su ancho, agregué espacio interior mediante "padding" e incorporé un color de fondo, un borde y esquinas redondeadas. De esa manera, cada opción de contacto adquirió una apariencia de tarjeta.

Luego, actualicé la página en Chromium para checar el resultado. Las opciones de contacto ahora se mostraban como tarjetas individuales, manteniendo su alineación y separación gracias a Flexbox.

Para registrar este último cambio, ejecuté "git status", "git add .", nuevamente "git status" y "git commit .". Después escribí el mensaje correspondiente en Visual Studio Code y envié el commit a GitHub con "git push origin main".

Ya para terminar, revisé el historial en GitHub y todo se veía bien.

De local a global: publicación del sitio web

Después de terminar el desarrollo de la página web, el siguiente paso fue publicarla en Internet para que cualquier persona pudiera visitarla.

Publicación del sitio mediante GitHub Pages

Para comenzar, ingresé a la página principal del repositorio en GitHub.

Después seleccioné el botón de "Settings" para acceder a las opciones de configuración del repositorio.

Dentro de los ajustes, ingresé al apartado "Pages". En la configuración de publicación, seleccioné la rama "main" como fuente del sitio web.

Luego presioné el botón "Save" para guardar la configuración. GitHub mostró un mensaje de confirmación indicando que la fuente de publicación había sido guardada.

Tras actualizar la página de configuración, pude comprobar que GitHub Pages había publicado el sitio correctamente y mostraba un enlace para visitarlo.

Finalmente, seleccioné la opción "Visit site" para abrir la página en una nueva pestaña del navegador. De esta manera, el sitio dejó de estar disponible únicamente en mi computadora y pasó a ser accesible desde la red.

Extra: Configuración de un dominio personalizado

GitHub Pages permite publicar una página web gratuitamente utilizando una dirección proporcionada por GitHub. Sin embargo, también es posible utilizar un dominio personalizado para que el sitio tenga una dirección propia.

En mi caso, adquirí el dominio de mi página mediante Porkbun. A continuación, mostraré brevemente cómo buscar un dominio y comenzar el proceso de compra. Este procedimiento es totalmente opcional y no es indispensable para publicar una página web utilizando GitHub Pages.

Primero, ingresé a la página principal de Porkbun:

Después escribí "buho.hacker" en el buscador para consultar las extensiones de dominio disponibles.

Porkbun mostró diferentes opciones de dominio junto con sus precios. Para este ejemplo, elegí "buho.hacker.dev" sin completar la compra.

Para agregar el dominio al carrito, hice click en el símbolo "+" que aparece junto a la opción elegida.

Después apareció la opción "Checkout", que permite continuar con el proceso de compra.

Al hacer click en esa opción, Porkbun mostró el carrito de compras con el dominio elegido y la información correspondiente. Desde esta página es posible revisar los detalles antes de continuar con el pago.

Una vez adquirido un dominio, este aparece en la lista de dominios de nuestra cuenta. Desde ahí podemos acceder a su configuración DNS, la cual es necesaria para conectarlo con servicios como GitHub Pages.

En la siguiente captura se muestra la opción DNS correspondiente a mi dominio personal, "adal.work", que adquirí anteriormente.

Una vez adquirido el dominio, fue necesario configurarlo para que este mandara a mi página publicada mediante GitHub Pages. Para eso, utilicé la configuración DNS de Porkbun y seguí las instrucciones que aparecen en la documentación oficial de GitHub.

GitHub explica a detalle cómo agregar un dominio personalizado al repositorio, configurar los registros DNS correspondientes y habilitar HTTPS. Puedes consultar el procedimiento en Managing a custom domain for your GitHub Pages site.

También es recomendable verificar la propiedad del dominio para evitar que otros usuarios puedan utilizarlo en sus propios sitios de GitHub Pages. Este procedimiento se explica en Verifying your custom domain for GitHub Pages.

Siguiendo estos pasos, pude publicar mi página personal utilizando mi propio dominio. De esta forma concluye el proceso de desarrollo y publicación de un sitio web.
